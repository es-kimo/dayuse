## 🛠 주요 엔지니어링 개선 및 안정화 내역

### 1. Flyway V6 프로덕션 마이그레이션 스크립트 추가
- 파일: `backend/src/main/resources/db/migration/V6__create_challenge_period_settlements.sql`
- 내용:
  - MySQL 8.0 환경에서 주 N회 구간 정산 엔티티 저장을 위한 `challenge_period_settlements` 테이블 DDL 정의
  - 복합 유니크 제약 `uk_participant_period_index(challenge_participant_id, period_index)` 및 외래키 인덱스 추가
  - 기존 `deposit_report_items` 테이블의 `daily_record_id` 컬럼 널러블(`NULL`) 변경 및 `period_settlement_id` 컬럼 추가/인덱싱

### 2. 종합 E2E 및 회귀 검증 테스트 스위트 (`V03RegressionAndE2EIntegrationTest`)
- 파일: `backend/src/test/kotlin/com/dayuse/domain/v03/V03RegressionAndE2EIntegrationTest.kt`
- 시나리오:
  1. **복합 E2E 유저 시나리오**:
     - 챌린지 생성 시 모임원 일괄 등록 (개별 약정금 설정)
     - 주 3회 10일 챌린지 진행 중 조기 달성, 4일차 초과 인증, 미달 참가자 1회 인증
     - 1구간(7일) 자연 종료 후 상태 판정 (`ACHIEVED` vs `NEEDS_CONFIRMATION`)
     - 타인 확정 차단 (403), 진행 중인 2구간 확정 차단 (400), 본인 확정 성공 (`CONFIRMED_FAILED`), 멱등성 검증
     - 미납 기록 조회 (`isPeriod = true`), 입금 신고 (`WAITING_CONFIRMATION`), 호스트 입금 승인 (`CONFIRMED`)
     - 단축 2구간(3일) 목표치 산출 검증
     - 종료 후 다시 시작하기 시 가변 기간(10일) 및 주기(`WEEKLY_N`, 3) 온전한 계승 검증
  2. **기존 매일형 챌린지 회귀 검증**:
     - 14일 `DAILY` 챌린지 생성, 일일 인증, `DailyRecord` 기반 벌금 부과 및 입금 정산 흐름의 100% 하위 호환성 확인
  3. **인가 및 IDOR 격리 검증**:
     - 타 모임 및 외부인 요청 시 차단 확인
  4. **웹 푸시 알림 필터링 검증**:
     - 주 N회 구간 목표를 이미 달성한 유저는 당일 미인증 상태여도 알림 대상에서 제외됨을 확인
