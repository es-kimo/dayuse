## 1. 개요 및 설계 원칙

본 문서는 dayuse 프론트엔드 코드베이스의 20개 실제 라우트와 9개 모달/바텀시트 컴포넌트를 전수 조사하여 상태별(Empty, Loading, Error, Success) 매트릭스를 수립하고, 모바일 중심의 신규 UI 프로토타입(`docs/screens/*.html`)을 실제 프로덕션 컴포넌트와 1:1로 매핑한 기준 문서입니다.

### 3대 핵심 설계 원칙
1. **가정 기반 작성 배제**: `frontend/src/App.tsx` 및 컴포넌트 트리에 실제 존재하는 페이지만을 대상으로 작성하며 가상의 화면을 임의 추가하지 않습니다.
2. **도메인 불변성 유지**: 참가, 인증, 공동 완료, 중단, 정산, 예치금 등 기존 비즈니스 정책 및 API 데이터 스키마는 일체 변경하지 않고 순수 UX/UI 레이아웃 및 사용성 개선으로 한정합니다.
3. **접근성 결함 무관용**: A/B 실험 비교군과 대조군 모두에서 웹 접근성(A11y), 키보드 포커스, 폰트 명암비, 반응형 이미지 비율을 동일하게 보장합니다.

## 2. A/B 실험 포함 및 제외 분리 기준

v0.8에서는 모바일 개편 효과를 정밀 측정하기 위해 화면의 성격에 따라 A/B 실험 대상과 공통 신규 UI 적용 대상을 엄격히 분리합니다.

```mermaid
flowchart TD
    User([사용자 접근]) --> IsAuth{인증 상태 또는 화면 성격}
    IsAuth -- "비로그인 (랜딩/로그인)" --> Common[공통 신규 UI 적용 (실험 제외)]
    IsAuth -- "외부 공개/공유 링크" --> Common
    IsAuth -- "법적 고지/정책 화면" --> Common
    IsAuth -- "로그인 후 개인 조작 화면" --> ABTest[A/B 실험 대상 배정 (v0.7 대조군 vs v0.8 개편군)]
    
    Common --> Safe[배정 혼선 방지 및 온보딩/공유 일관성 확보]
    ABTest --> Metrics[핵심 지표 측정: 오늘 할 일 인증 완료율, 모임 유지율, 이탈률]
```

### 1) A/B 실험 대상 (로그인 후 개인 조작 서비스 화면)
- **대상 화면**: 홈(`TodayPage`), 모임 목록/상세(`GroupsPage`, `GroupDetailPage`), 챌린지 상세(`ChallengeDetailPage`), 인증 모달(`VerificationModal`), 정산 화면(`SettlementManagePage`), 프로필(`ProfilePage`)
- **선정 이유**: 사용자의 일상 루틴과 조작 빈도가 높은 핵심 퍼널로, 신규 UI의 엄지 조작 영역(Thumb Zone), 할 일/피드 분리가 인증 완료율과 리텐션에 미치는 실질적 인과관계를 측정하기 위함입니다.

### 2) 공통 신규 UI 적용 (A/B 실험 제외)
- **대상 화면**: 로그인(`LoginPage`), 카카오 콜백(`KakaoCallbackPage`), 모임 초대 수락(`InviteLandingPage`), 공개 공유 페이지(`PublicShareLandingPage`), 정적 정책 페이지(`TermsPage`, `PrivacyPage`, `AboutPage`, `GuidePage`, `ContactPage`)
- **제외 이유**:
  - 비로그인 유저가 A/B 버킷에 따라 다른 온보딩 화면을 보게 될 경우 유입 혼선 및 브랜드 인지도 저해 발생
  - 외부 카카오톡/인스타그램 등으로 공유된 결과물(`PublicShareLandingPage`)은 일관된 브랜드 경험을 전달해야 함
  - 이용약관 및 개인정보처리방침 등 정책 문서는 실험 대상이 아닌 법적 고지물이므로 단일 디자인 적용

## 4. 화면별 개편안 및 실험 대상 상세 명세 (F01-2)

### [카테고리 1] 랜딩·로그인
- **화면명**: `LoginPage` (`/login`)
- **연결 목업**: [`docs/screens/01-login.html`](screens/01-login.html)
- **실험 포함 여부**: **공통 신규 UI 적용 (실험 제외)**
- **개편 내용**:
  - 모바일 뷰포트에서 상단 브랜드 비주얼(Dayu 마스코트)과 3줄 핵심 가치 제안 카피 명확화
  - 하단 엄지 영역(Thumb Zone)에 '카카오 1초 로그인' 고정 버튼 배치
  - 인앱 브라우저(카카오톡/인스타 인앱) 감지 시 외부 브라우저 호출 안내 가이드 연계
- **유지 사유**: 카카오 OAuth 2.0 리다이렉트 흐름 및 기존 토큰 스토리지 규격 100% 유지
- **확인 상태**: 기획 확정

### [카테고리 2] 홈·인증 피드
- **화면명**: `TodayPage` (`/today`)
- **연결 목업**: [`docs/screens/03-today.html`](screens/03-today.html)
- **실험 포함 여부**: **A/B 실험 대상**
- **개편 내용**:
  - **Hero 섹션 분리**: 화면 상단에 '오늘 내가 완료해야 할 인증 액션 카드'를 대형 크기로 고정 배치 (남은 시간 카운트다운 및 1-Tap 인증 버튼)
  - **친구 피드 타임라인 분리**: 하단 스크롤 영역에 같은 모임 친구들의 실시간 인증 피드를 인스타그램 스토리/피드 형태로 배치
  - '오늘 할 일'과 '친구 피드'가 뒤섞여 내가 무엇을 해야 하는지 인지하지 못하던 기존 문제 완전 해결
- **유지 사유**: `api/today.ts` 엔드포인트의 데이터 구조 그대로 활용
- **확인 상태**: 기획 확정

## 5. 모바일 UX/UI 디자인 가이드라인 (F01-3)

### 1) Thumb Zone (엄지 영역) 레이아웃 원칙
- **Primary CTA (인증하기, 참여하기, 저장하기)**: 스크린 하단 80px 내의 자연스러운 엄지 조작 영역에 전체 너비 버튼 또는 플로팅 바텀 바로 고정 배치
- **네비게이션 & 바텀시트**: 모달 대신 화면 하단에서 밀려 올라오는 Bottom Sheet를 기본 컨테이너로 사용 (`components/ui/BottomSheet.tsx` 활용)
- **위험 액션 (모임 나가기, 챌린지 중단)**: 상단 우측 보조 메뉴 또는 2단계 확인 AlertDialog로 분리하여 오조작 방지

### 2) Anti-AI 획일성 방지 원칙
- **과도한 글래스모피즘/그라데이션 지양**: 인위적이고 몽환적인 그라데이션 남발을 금지하고, 데이유즈 시그니처 옐로우/오렌지 포인트와 뉴트럴 그레이(#F8F9FA, #FFFFFF, #1A1A1A) 위주의 명료한 대비 유지
- **무의미한 중첩 카드 제거**: 카드 안에 카드가 중첩되는 형태를 지양하고, 얇은 디바이더(`border-subtle`)와 여백(`gap-3`, `gap-4`) 기반의 경량화된 계층 구조 채택
- **획일적 아이콘 남용 지양**: 불필요한 장식용 아이콘 대신 간결하고 직관적인 한글 라벨과 명확한 타이포그래피 위계로 전달

### 3) 여백 및 그리드 규칙
- **화면 가로 여백**: 모바일 좌우 패딩 `px-4` (16px) 통일, 카드 내부 패딩 `p-4` (16px)
- **카드 간 간격**: 리스트 간격 `space-y-3` (12px), 섹션 간 간격 `mt-6` (24px)
- **터치 타겟 크기**: 모든 버튼과 터치 인터랙션 영역은 최소 `44px x 44px` 이상 보장
